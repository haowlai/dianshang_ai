## 二、Docker 机制与架构分析
1. **Docker Image 与 Container / Compose Group 的关系**：
   - `docker load -i minio_image.tar` 仅仅是向宿主机 Docker 引擎注册名为 `minio/minio:RELEASE.2023-03-20T20-16-18Z` 的本地基础镜像（Image）；
   - 容器分组（Project Group）是由 `docker-compose.infra.yml` 中的 `name: agentic-commerce` 决定的。
2. **执行流程验证**：
   - 导入镜像 -> 学生运行 `docker-compose -f docker-compose.infra.yml up -d` -> Docker 优先使用本地存在的该 Tag 镜像 -> 创建并挂载到 `agentic-commerce` 分组下；
   - 结论：**100% 依然在 `agentic-commerce` 里面，界面与教师机完全一致**。
3. **对比边界**：
   - 若采用 `minio.exe` 原生进程启动，则不进 Docker；若采用 `docker load` 则完全归属于该容器组。
