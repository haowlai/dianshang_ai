## 一、生产打包核心原则与架构分层

在开发阶段，本地目录充满了海量的临时文件（如前端 `node_modules` 占动辄 500MB、Python `.venv` 占 1GB、`__pycache__` 编译缓存等）。**严禁直接将未清洗的本地目录直接复制上传至生产服务器！**

打包的本质是**“提取纯净可执行物料，剔除一切研发脚手架”**：

```
                    ┌────────────────────────────────────────────────────────┐
                    │               本地工程开发目录 (包含全部文件)          │
                    └───────────────────────────┬────────────────────────────┘
                                                │
                     ┌──────────────────────────┴──────────────────────────┐
                     ▼                                                     ▼
      【分支 1: 原生部署打包流】                              【分支 2: 容器化镜像构建流】
                     │                                                     │
        ┌────────────┴────────────┐                           ┌────────────┴────────────┐
        ▼                         ▼                           ▼                         ▼
 [前端 npm build]          [后端 python build]         [docker build backend]    [docker build frontend]
        │                         │                           │                         │
  生成 dist/ 静态网页       生成 requirements.txt       生成生产镜像               生成生产镜像
        │                         │                           │                         │
        └────────────┬────────────┘                           └────────────┬────────────┘
                     ▼                                                     ▼
         [生成源码/静态归档 tar.gz]                              [docker save 导出镜像 .tar]
                     │                                                     │
                     ▼                                                     ▼
            【上传到 ECS 服务器】                                   【上传到 ECS 服务器】
```

## 二、前端打包实战 (NPM / PNPM Build)

### 2.1 生产环境变量隔离 (.env.production)
在 `frontend/` 目录下创建生产专用配置文件 `.env.production`：

```ini
# frontend/.env.production
# 生产模式下 API 统一走相对路径 /api/v1，由线上 Nginx 进行反向代理
VITE_API_BASE_URL=/api/v1
VITE_WS_BASE_URL=/api/v1/ws
VITE_APP_TITLE=AgenticCommerce 生产工作台
```

---

### 2.2 构建静态资源产物并压缩归档

在本地 Windows 或 Mac 打开终端，进入 `frontend` 目录：

```bash
# 1. 进入前端目录
cd frontend

# 2. 安装依赖 (使用锁版本文件，保证环境绝对一致)
pnpm install --frozen-lockfile
# 若使用 npm: npm ci

# 3. 执行生产构建
npm run build
# 构建完毕后，所有产物汇聚在 frontend/dist/ 目录下 (含 index.html, assets/*.js, assets/*.css)

# 4. 验证产物并将其打包为 tar.gz 压缩包 (方便上传传输)
tar -czvf ../frontend-dist.tar.gz -C dist .
cd ..
```

现在在根目录下就会生成一个体积通常只有 **2MB ~ 5MB** 的 `frontend-dist.tar.gz` 纯净压缩包！

## 三、后端打包实战 (Python Build & 依赖固化)

### 3.1 使用 uv 生成精准锁定版 requirements.txt

开发时我们使用 `pyproject.toml`，但在生产部署时，为了防止依赖包版本自动升级引发兼容性报错，必须将所有第三方包锁定为固定版本号：

```bash
# 在项目根目录下执行：
uv pip compile pyproject.toml -o requirements.txt

# 查看生成的 requirements.txt，每一行都精确锁定了版本哈希：
# fastapi==0.115.0
# sqlalchemy==2.0.35
# pydantic==2.9.2
# ...
```

---

### 3.2 过滤缓存与垃圾文件并打包

使用 `tar` 命令排除所有非必需文件，打包核心后端源码：

```bash
# 排除 .venv、.git、__pycache__、临时日志与测试文件
tar --exclude='.venv' \
    --exclude='__pycache__' \
    --exclude='*.pyc' \
    --exclude='.git' \
    --exclude='logs/*' \
    --exclude='data/*' \
    --exclude='frontend' \
    --exclude='temp' \
    -czvf backend-prod.tar.gz \
    app/ conf/ prompts/ main.py requirements.txt pyproject.toml
```

生成的 `backend-prod.tar.gz` 体积通常仅在 **几十 KB 到 1MB 之间**，极易传输！

## 四、Docker 生产镜像构建实战 (Docker Build)

如果不采用原生部署，而是采用云原生容器交付，就需要将前后端分别打成 Docker 镜像。

### 4.1 后端多阶段构建 Dockerfile 生产调优
项目根目录下的生产标准 [Dockerfile](file:///d:/code/dianshang/Dockerfile)：

```dockerfile
# ── Stage 1: 构建依赖与轮子 ──
FROM python:3.12-slim AS builder

WORKDIR /build
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    curl \
    && rm -rf /var/lib/apt/lists/*

COPY --from=ghcr.io/astral-sh/uv:latest /uv /bin/uv
COPY pyproject.toml ./
RUN uv pip compile pyproject.toml -o requirements.txt
RUN pip install --no-cache-dir --prefix=/install -r requirements.txt

# ── Stage 2: 最终轻量运行时镜像 ──
FROM python:3.12-slim AS runner

WORKDIR /app
ENV TZ=Asia/Shanghai \
    PYTHONUNBUFFERED=1

RUN apt-get update && apt-get install -y --no-install-recommends \
    libpq5 \
    curl \
    && rm -rf /var/lib/apt/lists/*

# 从构建阶段复制已编译好的 Python 库
COPY --from=builder /install /usr/local
# 复制应用源码
COPY . .

# 暴露端口并运行
EXPOSE 8002
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8002", "--workers", "2"]
```

**本地构建后端镜像命令**：
```bash
docker build -t agentic-backend:v1.0.0 -f Dockerfile .
```

---

### 4.2 前端 Nginx 静态镜像构建
文件位置：`frontend/Dockerfile`

```dockerfile
# ── Stage 1: 前端代码构建 ──
FROM node:20-alpine AS builder
WORKDIR /app
COPY package.json pnpm-lock.yaml* ./
RUN npm install -g pnpm && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build

# ── Stage 2: 生产 Nginx 托管 ──
FROM nginx:alpine AS runner
COPY --from=builder /app/dist /usr/share/nginx/html
# 注入支持 Vue Router 的 Nginx 基础配置
RUN echo 'server { listen 80; location / { root /usr/share/nginx/html; try_files $uri $uri/ /index.html; } }' > /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**本地构建前端镜像命令**：
```bash
docker build -t agentic-frontend:v1.0.0 -f frontend/Dockerfile ./frontend
```

## 五、Docker 离线镜像导出与恢复 (Docker Save & Load)

在实际教学或企业交付中，**由于生产服务器可能无法高速访问 Docker Hub，甚至处于私有内网环境**，此时通过 `docker save` 导出离线镜像包是 100% 可行的高可靠方案！

### 5.1 本地镜像打包导出 (docker save)

在本地电脑上，将刚刚构建出来的后端、前端，以及官方的 Postgres/Redis/MinIO 一起打包成一个离线镜像总包：

```bash
# 将 5 个生产镜像合并导出为一个压缩归档文件
docker save \
    agentic-backend:v1.0.0 \
    agentic-frontend:v1.0.0 \
    pgvector/pgvector:pg16 \
    redis:7-alpine \
    minio/minio:RELEASE.2023-03-20T20-16-18Z \
    | gzip > agentic-images-v1.0.0.tar.gz
```

该压缩包生成在当前目录，大小约 400MB 左右。

---

### 5.2 生产服务器离线加载 (docker load)

将该 `agentic-images-v1.0.0.tar.gz` 文件上传到阿里云 ECS 服务器后，在服务器终端执行：

```bash
# 这一行命令自动还原所有 5 个镜像，完全不需要联网拉取任何 Docker Hub 镜像！
docker load -i agentic-images-v1.0.0.tar.gz

# 检查已成功导入的镜像清单：
docker images
```

## 六、本地一键自动化打包脚本实操

为了避免每次手动敲十几行打包命令，我们为 Windows 开发者编写了一键批处理脚本 [`scripts/build_offline.bat`](file:///d:/code/dianshang/docs/bushu/scripts/build_offline.bat)：

### 脚本使用方法：
在本地 Windows 电脑上双击运行该脚本，它将自动按顺序完成：
1. 编译前端生产代码并打包 `frontend-dist.tar.gz`；
2. 锁定 Python 依赖并打包 `backend-prod.tar.gz`；
3. 执行 `docker build` 并通过 `docker save` 生成全量镜像包 `agentic-images-v1.0.0.tar.gz`；
4. 将所有交付物统一归档到根目录的 `release/` 文件夹中！
