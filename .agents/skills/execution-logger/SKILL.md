# AI 执行日志归档规范 (Execution Logger Skill)

## 1. 目标与定位
为了保证开发过程完全透明、操作可审计、决策可复盘，每次 AI 助手执行指令后，必须将本轮执行的全部全量日志写入项目根目录下的 `ailog/` 目录中。

---

## 2. 文件命名规范
日志文件存储路径：`ailog/`
文件名格式：
```text
ailog/YYYY-MM-DD_HH-mm-ss_简要主题.md
```
示例：
- `ailog/2026-09-24_00-20-00_project_scaffolding.md`
- `ailog/2026-09-24_00-40-00_root_directory_cleanup.md`
- `ailog/2026-09-24_00-45-00_setup_ailog_skill.md`

---

## 3. 日志内容必须包含的要素 (不可遗漏)

每个日志文件采用标准 Markdown 格式，必须包含以下章节：

```markdown
# AI 执行日志：[任务主题]

- **执行时间**：YYYY-MM-DD HH:mm:ss (本地时间)
- **对话编号**：[Conversation ID]
- **执行模型**：[AI Model Name]
- **触发类型**：[用户明确指令 / 自动验证 / 异常修复]

---

## 一、用户需求与背景
- 完整记录用户此轮发送的指令（User Request）
- 上下文背景、当前开发阶段与所涉及的相关文档或代码文件

---

## 二、分析与决策过程
- 针对用户需求的深入理解与逻辑推演
- 架构设计考量、冲突排查与关键决策依据
- 对比方案与最终选择理由

---

## 三、具体执行操作清单
### 1. 文件创建与修改
- 详细列出新建（NEW）、修改（MODIFY）、删除（DELETE）的文件绝对路径与相对路径
- 记录每个文件的关键改动点说明

### 2. 执行的命令与工具调用
- 运行的 Shell / PowerShell 命令、执行参数与返回状态
- 涉及的第三方 API 或工具交互记录

---

## 四、执行结果与验证
- 自动化验证（命令输出、状态码、文件树检查结果）
- 检查清单完成度核验

---

## 五、当前系统状态与下一步待办
- 当前代码库目录与 Git 状态简述
- 遗留问题、风险提示或后续建议待办项
```

---

## 4. 强制执行准则
1. **全量记录**：严禁只记录简报或跳过细节，工具调用、具体改动的文件列表及关键代码骨架必须明确记录。
2. **及时落盘**：在每次向用户回复最终结果之前，必须先将日志文件写入 `ailog/` 目录。
3. **独立自洽**：单份日志文件必须包含足够的上下文，确保脱离会话历史后，用户或其他开发者能独立看懂该次操作的前因后果。
